# وثيقة الاسترداد الآمن — Colab Desktop Runner

> هذه الوثيقة تذكر **أسماء** الأسرار وخطوات الإعداد فقط. **لا تحتوي أي قيمة سرية** ولا يجوز أن تحتوي.

## 1) المفاتيح والأسرار المستخدمة

| الاسم | النوع | المكان | الغرض |
|---|---|---|---|
| `release-key.jks` | Android Keystore (RSA) | جهاز المالك فقط — خارج أي مستودع | توقيع APK (بصمة الشهادة SHA-256: `4582a8a1…a8551a`) |
| `key.properties` | ملف خصائص Gradle | بجوار الـ keystore محليًا — خارج أي مستودع | تمرير كلمات مرور الـ keystore للبناء |
| مفتاح Ed25519 الخاص | 32 بايت خام (binary) | جهاز المالك: `update-signing/update_signing.priv` (صلاحيات 0600) — خارج أي مستودع | توقيع بيان التحديث `latest.json` |
| `UPDATE_SIGNING_KEY_HEX` | GitHub Repository Secret (على المستودع الخاص) | Settings → Secrets → Actions | نفس مفتاح Ed25519 بصيغة hex ليستخدمه workflow الإصدار |

**فصل المفاتيح**: مفتاح توقيع APK (Android Keystore) **مستقل تمامًا** عن مفتاح توقيع البيان (Ed25519). تسريب أحدهما لا يمسّ الآخر.

## 2) سيناريوهات الاسترداد

### أ) فقدان مفتاح Ed25519 الخاص (توقيع البيان)
1. ولّد زوجًا جديدًا (32 بايت seed) على جهاز غير متصل.
2. حدّث `manifestPublicKeyHex` و`manifestKeyId` (مثل `ed25519-2026-01`) في `lib/core/update_config.dart`.
3. أصدر تحديثًا **بالمفتاح القديم** (إن كان ما يزال سليمًا غير مسرّب) يحمل المفتاح الجديد داخل التطبيق — سلسلة ثقة موقّعة.
4. إن كان القديم **مسرّبًا/مفقودًا نهائيًا**: لا يمكن دفع مفتاح جديد عبر قناة التحديث (سيُرفض). الحل الوحيد: إصدار APK جديد عبر متجر/قناة التثبيت اليدوي، وإبطال إصدار `latest.json` القديم بحذف الأصول من الـ Release.
5. حدّث السر `UPDATE_SIGNING_KEY_HEX` بالقيمة الجديدة.

### ب) تسريب مفتاح Ed25519
- احذف فورًا `latest.json` و`latest.json.sig` من أحدث Release عام (يمنع أي بيان مزوّر لاحق من العمل؟ لا — لكن يمنع الالتباس).
- ملاحظة أمان: البيانات لها `expiresAt` (90 يومًا) و`serial` متزايد — البيان المزوّر يحتاج serial أكبر من المخزَّن على جهاز المستخدم.
- اتبع (أ) خطوات 1–5.

### ج) فقدان Android Keystore
- **لا يمكن** إصدار تحديث لنفس التطبيق بشهادة مختلفة (أندرويد يرفض). 
- الوقاية: نسخ احتياطية مشفّرة للـ keystore في مكانين منفصلين غير متصلين.
- إن فُقد نهائيًا: يلزم نشر تطبيق جديد بمعرّف حزمة جديد (خسارة قاعدة التثبيت).

### د) تسريب توكن GitHub
- أبطِل التوكن من GitHub → Settings → Developer settings.
- أنشئ توكنًا جديدًا بأقل صلاحيات، وحدّث بيئة العمل المحلية فقط (لا يدخل أي مستودع).

## 3) قواعد ثابتة
- المصدر يبقى في المستودع **الخاص**؛ المستودع العام لملفات التوزيع فقط.
- لا مفاتيح/توكنات داخل APK أو المستودعات أو التقارير — المفتاح **العام** Ed25519 فقط مثبّت داخل التطبيق.
- أي تغيير في `applicationId` أو شهادة التوقيع **ممنوع** (يكسر التحديثات).
