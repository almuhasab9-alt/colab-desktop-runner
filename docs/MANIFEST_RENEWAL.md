# تجديد بيان التحديث قبل انتهاء صلاحيته (90 يومًا)

بيان `latest.json` يحمل حقل `expiresAt` (90 يومًا من توليده). بعد انقضائه يرفض التطبيق البيان ويعرض «انتهت صلاحية بيان التحديث» — **لا يُثبَّت شيء منتهي الصلاحية أبدًا**.

## متى؟
- ضع تذكيرًا كل **75 يومًا** (هامش 15 يومًا).
- البيان الحالي (v1.1.1-rc.1): وُلّد 2026-07-22 وينتهي **2026-10-20T08:31:59Z**.

## كيف؟ (إعادة توقيع بدون إصدار جديد)
على جهاز المالك حيث المفتاح الخاص:

```bash
# 1) أعد توليد البيان بنفس بيانات الإصدار الحالي مع serial أعلى بواحد
UPDATE_SIGNING_KEY_FILE=~/update-signing/update_signing.priv \
python3 tools/release_pipeline.py \
  --new-apk <نفس-APK-الحالي> \
  --version-name <نفس-الاسم> --version-code <نفس-الرقم> \
  --serial <الرقم-التسلسلي-السابق+1> \
  --repo almuhasab9-alt/colab-desktop-runner-releases --tag <نفس-الوسم> \
  --old-apk <code>:<apk-قديم> ... \
  --out renew/

# 2) استبدل الأصلين على الـ Release (احذف القديمين ثم ارفع الجديدين)
gh release delete-asset <tag> latest.json -y
gh release delete-asset <tag> latest.json.sig -y
gh release upload <tag> renew/latest.json renew/latest.json.sig
```

## قواعد
- **serial يجب أن يزيد** عند كل إعادة توقيع (حماية من إعادة تقديم بيان قديم).
- لا تغيّر `versionCode` عند مجرد التجديد.
- تحقّق بعد الرفع: نزّل البيان بلا مصادقة وتأكد من صحة التوقيع وتاريخ `expiresAt` الجديد.

## سلوك التطبيق الموثّق
- لا تحديث متاح → «تطبيقك محدث» (البيان صالح لكن versionCode ≤ المثبّت).
- بيان منتهي الصلاحية → رسالة خطأ واضحة، لا تنزيل ولا تثبيت.
- بيان بمفتاح keyId غير معروف → يُرفض («مفتاح توقيع البيان غير معروف»).
